Build out the changes locally (do not commit) to fill in juniper section for conf/switch_commands.yml   In the current code design, with respect to juniper interfaces we currently support either QinQ mode, or public routed vlan mode.  Based on the current commands we run to set either the qinq mode, or public/routed vlans, the juniper section of the switch_commands.yml should contain a vender->juniper section that contains four different operations sections for "set_port_qinq", "set_port_public", "get_vlan_qinq", and "get_vlan_public".  References to "juniper" in the code should be made more generic ("network", or "network_driver"), and the specific areas of code that are executed when quads operates against defined interfaces will depend on the "vendor" field for the interfaces associated with the host.  When deciding switch commands to run (for set_port_qinq, set_port_public, get_vlan_qinq, get_vlan_public) if the interface in question has no "vendor" field, is set to None, or has a vendor for which we have no config definition, quads should emit a non-fatal warning message and continue with the current operation.  Under the cases where vendor is not know or no config exists, switch_config_applied should get flagged as true during a "move" operation, since the switch changes would be treated as a "no-op"

This would obviate the need to write separate code plugins for each specific switch vendor.  We would have a generic network driver, and the specifics of switch configuration changes are moved into conf/switch_commands.yml, with the only requirement being ssh access into the switch in question.
